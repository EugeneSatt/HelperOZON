# Источники, даты и сопоставимость

## Контракт одной метрики

До генерации/публикации зафиксируй кабинет, точный SKU, часовой пояс **отчёта**, название метрики, точные названия числителя/знаменателя, единицу счёта и охват трафика. Часовой пояс компьютера не доказывает часовой пояс источника. Источник фильтруется по SKU; после скачивания проверь состав XLSX — интерфейсный фильтр может не переноситься в файл.

Основной источник — «Аналитика → Воронка продаж» по точному SKU. Найди сопоставимые показы и переходы из соответствующих мест показа либо нативный показатель с объяснением его формулы. В примерах `views` — подтверждённый знаменатель, `clicks` — подтверждённый числитель; это рабочие имена, а не обещание названий столбцов Ozon. Не дели все просмотры карточки на показы только поиска/каталога. Если определение нативного показателя не воспроизводится по доступным данным, не подменяй его другой формулой: зафиксируй пробел и подготовь материалы без активной ротации.

Опциональный источник — «Продвижение → Оплата за клик → кампания → товар/подробный отчёт» либо «Аналитика продвижения» в подтверждённой товарной детализации. Сохраняй фиксированные кампании/размещения и определения. Если собираешь несколько кампаний, суммируй их непересекающиеся точные показы и клики SKU; не суммируй итог кампании с её детализацией. Пересекающиеся разные модели продвижения не объединяй без доказательства непересечения. CTR считай из сумм, не усредняй проценты. `use_ad_ctr=false` означает, что рекламный источник не участвует и не блокирует тест.

Сохраняй штатные CSV/XLSX без правок или точный текст интерфейса/скриншот с фильтрами, датами, SKU и полными числами. «1,2 тыс.» не равно известным 1200. Отсутствие строки не равно нулю. Время скачивания не равно времени учитываемых событий. Дату/момент обновления и ограничения источника фиксируй по реально видимым данным, не выдумывай постоянную задержку Ozon.

## Два режима

До выбора времени проверки собери также три полных дня по [правилам оценки трафика](traffic-and-cadence.md). Эти исторические данные используются для планирования частоты и не добавляются к показам тестируемых обложек.

Для выбранных пользователем уникальных показов/просмотров: знаменатель — «Уникальные посетители, всего» (увидели товар на любой странице Ozon), числитель — «Уникальные посетители карточки товара» (в выгрузке: «Уникальные посетители с просмотром карточки товара»). Точные определения проверь в текущей выгрузке. Это пользовательский CTR воронки по всем источникам, не поисковый или рекламный CTR. Готовая «Конверсия из поиска и каталога в карточку» и обычные «Посещения карточки товара» не заменяют эту пару.

Для этого источника используй `unit:period_unique` и `whole_days`. Каждый раз устанавливай в кабинете период от первого полного дня после подтверждения обложки до последнего завершённого дня. Сохраняй точный периодный итог, не сумму дневных уникальных. Порог 1000 относится к уникальным за этот интервал. Строка содержит `period_start` и `date` (конец включительно). Итог изменившегося периода заменяется только под тем же ключом периода; более длинный период — новая запись. При нескольких повторениях сводный CTR — отношение сумм числителей и знаменателей отдельных блоков с явной подписью «взвешенное сравнение блоков»; это не уникальные люди всего теста.

`whole_days`: надёжная дневная детализация. Смена фото исключает весь день смены; считаются только полные завершённые дни после подтверждения фото и до следующей смены. Если фото проверено 28-го в 00:01, 28-е не становится полным днём автоматически. В 29-е можно запрашивать итог за 28-е, но он не учитывается для этого интервала; первый пригодный день — 29-е после его завершения. Минимальный объём — нижняя граница для завершённых блоков. Обложка может оставаться несколько дней, пока не наберётся согласованный объём.

Если источник считает дневных уникальных посетителей, разрешён только `whole_days` и отдельно согласованная взвешенная дневная метрика: сумма дневных числителей / сумма дневных знаменателей. Она не равна нативной метрике уникальных людей за весь многодневный период. Не складывай дневную уникальность под подписью «уникальные покупатели теста». Если пользовательский норматив относится именно к уникальности всего периода, потребуется отдельный сопоставимый источник/дизайн; не применять норматив автоматически к сумме дней.

`intraday_counts`: только аддитивные показы/переходы и проверенная внутридневная детализация. Пользователь принимает приблизительную привязку по моментам чтения: поздние события могут попасть по другую сторону смены фото. Снимок после подтверждения опубликованного фото задаёт начальные значения. Снимок перед сменой — конечные. Период между чтением и подтверждением следующей публикации не приписывай обеим обложкам. Новая обложка получает свою свежую границу. Этот режим не делает наблюдение рандомизированным A/B-тестом.

## Обнуление в полночь

Один день хранится по ключу `источник + дата`, внутри привязки кабинета/SKU/контракта. Ноль за новую дату нормален. Вычитание 0 − вчерашние 2000 запрещено. Ноль за ту же дату после большего значения — коррекция/смена фильтра, требующая проверки.

Пример для одной B без смен через полночь:

- При старте B дневной счётчик был 1200 показов / 30 переходов.
- В 23:55 был 2000 / 50 — это ещё не финальный итог дня.
- В 00:00 появился 0 / 0 за **новую дату**.
- Утром получен итог за вчера 2100 / 54, сегодня 100 / 6.
- Для B: `(2100 − 1200) + 100 = 1000` показов и `(54 − 30) + 6 = 30` переходов; CTR = 3%.

Закрытие интервала блокируется до получения каждого прошедшего дня для каждого включённого источника. Если пропущены двое суток, нужны оба дня, а не только вчера. Сохраняй A/B на месте, пока восстанавливаются данные; не менять фото по догадке. Удержание ограничено пользовательским `max_interval_hours`, после него пауза.

Признак `settled=true` ставь только для прошлой даты и после проверки законченного периода/доступной задержки по источнику. Полночь сама по себе не означает финализацию. Если источник ещё пересчитывается, оставляй `settled=false`. Более поздний итог **заменяет** прежнюю запись за дату. Идемпотентные повторные наблюдения не начисляют повторные показы. Если исправлен уже завершённый день закрытого интервала, локальный процесс снимает подтверждение результата и требует сверки. Не распределяй поздние исправления между внутридневными обложками пропорционально времени.

## Условия

В начале — полная исходная проверка цены/акций/остатков/доставки/видимых рекламных настроек. При проверках обложки — короткий снимок условий карточки. Цена — наблюдаемая покупателем при одном регионе и способе оплаты; цены с Ozon Картой и иными условиями не смешивать. Допуск фиксируется до теста. Изменившееся условие исключает текущий блок, а не «корректируется» формулой к прежней цене. При возобновлении новый блок сравнения начинается заново для A и B; прежние данные доступны в истории отдельно.

Неизвестную историческую цену/ставку не подменяй текущей. Неизменность между краткими проверками не гарантируется. При резком изменении состава трафика проверь кампании/размещения и отметь ограничения даже при прежних видимых настройках.
