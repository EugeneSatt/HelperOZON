# 18 показателей и честное сравнение

`analyze.py` принимает числа, булевы значения и явные пропуски. Проценты храни долями 0..1. Значение 0 не равно отсутствию данных. Поисковая позиция начинается с 1; «не найден» = null с указанием глубины просмотра.

18 строк, из них 14 участвуют в индексе; полный знаменатель весов = 18. Это адаптация исходного структурного индекса, а не доказанная модель продаж и не оценка качества карточки. Число фото, знаков, отзывов и объём продаж не доказывают, что конкретная правка улучшит результат. Не используй их механически как цели правок.

## Сопоставимость

У наблюдения должны совпадать с собственной строкой: `basis` (определение), `period`, `scope`, `region`, `query_set`. Данные должны иметь проверяемый `source_id`. Совпадающий произвольный текст `basis` не делает разные метрики сопоставимыми: за соответствие реальным определениям отвечает этап сбора.

- `basis` описывает показатель, способ расчёта и ограничения охвата. `mpstats_orders_rub` отличается от фактической выручки/выкупов Ozon Seller.
- `period` равен `snapshot` для текущих характеристик/цен/накопленного рейтинга или паре дат `[start,end]` для периодических показателей. Для текущего поиска укажи точный временной интервал снимка в `basis`, например `live_general_rank_2026-10-26T14:10+03:00`. Нельзя сравнивать его с 30-дневной средней.
- `scope` должен отражать фактический охват: `sku`, `product_group`, `variant`, `selected_offer` и т.п. Для группы укажи состав вариантов в источнике. Метрика выбранного продавца не равна общей метрике всех предложений карточки.
- У `search_position` дополнительно обязателен непустой `query_set` с одинаковым порядком/агрегацией запросов и `region`. Общая средняя позиция MPStats и позиция по трём выбранным запросам Ozon Seller — разные показатели.
- Негатив среди последних отзывов и негатив по всей истории — разные `basis`. Не подменяй точную долю прокси в той же строке.
- Для CTR и чужих конверсий нужна сопоставимая доступная выгрузка. Агрегат категории, рекламный CTR, оценки выручки или средний показатель группы не являются воронкой чужого SKU. При обычном внешнем аудите чужие CTR и конверсии, как правило, недоступны: оставь null.

Отдельный блок собственных фактических показателей в отчёте может содержать дополнительные наблюдения Ozon Seller. Не передавай их вместо сопоставимой строки MPStats, если определения различаются.

Неполное наблюдение объёмов FBO/FBS может сделать сравнение сумм/заказов разных продавцов некорректным даже при одинаковом названии поля. В таком случае сохрани исходное число, установи `comparison_eligible=false` с объяснением и исключи его из индекса. Сам факт одинакового API не доказывает одинаковую полноту охвата.

## Цвета и индекс

Для числовых строк бери медиану доступных сопоставимых конкурентов. Больше: зелёный выше медианы на >5%, жёлтый в ±5%, красный ниже. Меньше: обратное. При нулевой медиане точное совпадение жёлтое, улучшение зелёное, ухудшение красное. Для нулевой базы процент разрыва не определён; показывай абсолютную разницу.

Булевы строки: своё `true` зелёное; своё `false` при строгом большинстве `true` у сопоставимых конкурентов красное, иначе жёлтое. Неизвестное значение не равно `false`.

В индекс включай только строки со своим наблюдением и минимум тремя сопоставимыми конкурентами. При 1–2 конкурентах можно показать медиану и цвет как описательное сравнение, но строка в индекс не входит. Это техническое правило устойчивости версии, а не статистическая гарантия.

Индекс = сумма весов зелёных/жёлтых включённых строк / сумма весов включённых строк × 100, округление половины вверх. При нулевом знаменателе индекс = null. Показывай рядом:

- количество включённых строк из 14 и вес из 18;
- включённые ключевые показатели из 4;
- число конкурентов и отдельные причины пропусков;
- «частичное сравнение», если исключена хотя бы одна строка.

Не называй частичный индекс «карточка на уровне топа». Отдельно перечисляй красные строки и недоступные ключевые показатели. При одном подтверждённом недостатке выдай одно действие; отсутствие трёх проблем не является ошибкой.
