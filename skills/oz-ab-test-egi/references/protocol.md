# Протокол локального процесса

Все JSON формирует агент из фактических наблюдений, пользователь их не заполняет. Пути к файлам должны существовать. Приведённые названия кабинета/SKU, даты и числа — учебный пример, не готовая конфигурация для запуска. Данные времени всегда ISO с часовым поясом. Фактические снимки не старше 15 минут; это свежесть чтения, а не обещание свежести событий Ozon.

## Файл подготовки

```json
{
  "test_id": "oz-cover-001",
  "title": "Фактическое название товара",
  "original": "/absolute/path/original.jpg",
  "image_generation_authorized": false,
  "config": {
    "target_funnel_ctr": 3,
    "use_ad_ctr": false,
    "views_per_interval": 1000,
    "mode": "whole_days",
    "min_hours": 24,
    "max_interval_hours": 168,
    "cycles": 1,
    "max_generations": 0,
    "finish_policy": "leader",
    "price_tolerance_pct": 0
  },
  "binding": {
    "seller": "Устойчивое обозначение фактического кабинета",
    "sku": "Фактический SKU строкой",
    "timezone": "Europe/Moscow",
    "media_order": ["Фото 2: описание", "Видео: описание"],
    "sources": {
      "funnel": {
        "definition_id": "verified-funnel-definition-1",
        "scope_id": "exact-sku-and-fixed-filters",
        "metric_name": "Фактически подтверждённое название CTR воронки",
        "numerator_label": "Подтверждённое название числителя",
        "denominator_label": "Подтверждённое название знаменателя",
        "traffic_scope": "Фактический охват источника",
        "unit": "events",
        "granularity": "day",
        "settled_day_report_available": true
      }
    }
  },
  "probe": {}
}
```

`probe` заполняется наблюдением из следующего раздела. При рекламе включи `use_ad_ctr:true`, пользовательские `target_ad_ctr`, `ad_views_per_interval` и контракт `binding.sources.ads` с фиксированными кампаниями/размещениями. `scope_id` меняется при изменении набора кампаний/фильтров. Нельзя просто сохранить старый ID при новом охвате.

При дневных уникальных — `unit:daily_unique` и `daily_unique_aggregation_accepted:true` после объяснения/согласования взвешенной дневной метрики. Для внутридневного режима — `mode:intraday_counts`, `accept_approximate_boundaries:true`, во всех включённых контрактах `unit:events`, `granularity:intraday`, `intraday_probe_passed:true`. Флаги отражают реальную проверку и согласование; JSON не заменяет их.

Для уникальных за весь интервал: `unit:period_unique`, `granularity:period`, `mode:whole_days`. В строках дополнительно `period_start:YYYY-MM-DD`; `date` — последний день включительно. Бери оба числа из одной выборки всего периода. Итоги отдельных дней не заменяют итог объединённого периода. Для пробного источника допустим завершённый однодневный период.

## Визуальная проверка и условия

Объект `cover`:

```json
{
  "seller": "Устойчивое обозначение фактического кабинета",
  "sku": "Фактический SKU строкой",
  "timezone": "Europe/Moscow",
  "observed_at": "2026-10-28T12:00:00+03:00",
  "variant_sha256": "Фактический sha256 файла варианта",
  "first_image_matches": true,
  "other_media_unchanged": true,
  "media_order": ["Фото 2: описание", "Видео: описание"],
  "reopened": true,
  "evidence": ["/absolute/path/actual-source.txt"],
  "conditions": {
    "price": 1000,
    "currency": "RUB",
    "region": "Москва, фактический выбранный регион",
    "payment": "Фактические условия оплаты",
    "promotion": "Фактический бейдж либо подтверждённое отсутствие",
    "available": true,
    "delivery": "Фактический срок доставки"
  }
}
```

Обязательно реально увидеть фото; одного текста accessibility недостаточно. Если инструмент не сохраняет скриншот в файл, сохрани доступный точный текст как первичный источник и опиши визуальную проверку в нём. Не выдумывай путь к скриншоту. Для `init` SHA вычисляется от полного исходника A. `media_order` описывает остальные медиа, кроме изменяемого первого фото. Требования к размерам/формату изображения сверяются в текущем интерфейсе Ozon, не берутся из примера WB.

## Наблюдение

```json
{
  "observation_id": "unique-id",
  "seller": "Устойчивое обозначение фактического кабинета",
  "sku": "Фактический SKU строкой",
  "timezone": "Europe/Moscow",
  "observed_at": "2026-10-28T12:02:00+03:00",
  "cover": {},
  "rows": [
    {
      "source": "funnel",
      "definition_id": "verified-funnel-definition-1",
      "scope_id": "exact-sku-and-fixed-filters",
      "date": "2026-10-27",
      "captured_at": "2026-10-28T12:01:00+03:00",
      "settled": true,
      "views": 2100,
      "clicks": 54,
      "url": "URL фактически открытого отчёта",
      "evidence": ["/absolute/path/actual-export.xlsx"]
    }
  ]
}
```

`cover` — заполненный предыдущий объект. Для рекламы добавь строку `source:ads` с её контрактом. Один источник/дата — одна нормализованная строка, не итог плюс детализация. `observed_at` — завершение сбора; `captured_at` строк не позже него. `settled:false` — промежуточный счётчик. При переходе суток нужны все пропущенные прошлые даты с `settled:true`; при `intraday_counts` также свежая текущая дата для каждого источника. Строки могут иметь разные даты, но их охват не должен меняться. `settings_changed:true` указывается при фактически обнаруженном изменении рекламы.

Первичные файлы копируются в `evidence/` по хешу; состояние содержит журнал наблюдений и дневные значения. Повтор одного ID с тем же содержимым не начисляет данные повторно; ID с другим содержимым отклоняется. Исправления сохраняй новым ID и новым временем чтения.

## Команды

Выполняй из каталога скилла либо используй абсолютный путь к скрипту:

```bash
python scripts/workflow.py init --test-dir /abs/oz-ab-tests/id --input /abs/setup.json
python scripts/workflow.py add-variant --test-dir /abs/oz-ab-tests/id --input /abs/review-B.json
python scripts/workflow.py start --test-dir /abs/oz-ab-tests/id --input /abs/authorization.json
python scripts/workflow.py next-action --test-dir /abs/oz-ab-tests/id
python scripts/workflow.py begin-ui --test-dir /abs/oz-ab-tests/id --input /abs/preflight.json
python scripts/workflow.py confirm --test-dir /abs/oz-ab-tests/id --input /abs/published.json
python scripts/workflow.py observe --test-dir /abs/oz-ab-tests/id --input /abs/observation.json
python scripts/workflow.py close --test-dir /abs/oz-ab-tests/id
python scripts/workflow.py report --test-dir /abs/oz-ab-tests/id
```

- `review-B.json`: `id`, `file`, `label`, `hypothesis`, `source:provided|chatgpt_image_gen`, `approved:true`; для генерации — `generation_name`.
- `authorization.json`: `active_test_authorized:true`, только при реальном разрешении пользователя.
- `preflight.json`: объект визуальной проверки **текущей прежней** обложки плюс `intent_id` из `next-action`. После успешного `begin-ui` можно выполнить одну смену в браузере по [порядку смены обложки](cover-change.md): загрузка/выбор готового варианта, перенос первым, однократное сохранение и обязательный reload страницы товаров. Скрипт её не выполняет. Повторно открытая галерея без reload не доказывает неудачу сохранения.
- `published.json`: проверка **целевой опубликованной** обложки плюс тот же `intent_id`. Если фото уже стоит и загрузки не было — `no_upload_needed:true`. Для `intraday_counts` добавь `snapshot` — полное новое наблюдение с целевым фото; текущие счётчики прочитаны после визуальной проверки публикации. Для `whole_days` начальная часть дня исключается, снимок счётчиков не нужен для назначения границы.

`reopened:true` для `published.json` означает реальное повторное открытие и проверку опубликованной карточки после сохранения и обновления страницы товаров. Новая миниатюра в кабинете подтверждает сохранение, но не заменяет проверку публикации. При статусе «Обновляется» сохраняй незавершённый intent: не выполняй `confirm` до фактической проверки нового фото у покупателя. Время обработки/модерации не начисляется новому варианту.

В новом тесте используй один проход. Начни с A и собери один интервал на каждый одобренный вариант в порядке добавления. После достижения объёма и готовности последнего интервала вызови `close` сразу. Скрипт выбирает лидера и запрашивает `confirm` итогового фото независимо от того, выполнен ли норматив CTR. У этого шага нет интервала сбора. Пока итоговое фото не проверено, состояние остаётся `awaiting_cover`. Сохранённые конфигурации с ранее заданными дополнительными кругами или `confirmation_multiplier` поддерживаются при продолжении существующих тестов.

`pause` принимает `{"reason":"Фактическая причина"}`. `resume` — `{"resume_authorized":true,"cover":{...}}`: для паузы по условиям создаёт новый блок сравнения, не смешивая эпохи. При незавершённой смене сверяет целевое или прежнее фото. Если целевое уже опубликовано, следующая операция — `confirm`, без повторной загрузки. Если осталось прежнее, повтор требует `repeat_ui_authorized:true` на основании явного указания пользователя.

`stop` принимает `{"stop_authorized":true,"variant":"A"}` либо конкретный вариант/`leader`. После него также нужно выполнить намерение и подтвердить фото. Текущий незавершённый интервал исключается. При `leader` без рассчитанного лидера команда отклоняется; уточни конкретное целевое фото.

При `reconcile_cover` неизвестно, успела ли прерванная смена попасть на карточку. Заново открой её, визуально сравни фото с сохранёнными кандидатами и выполни `reconcile --input /abs/actual-cover.json`. Вход — обычная проверка **фактического** фото плюс `intent_id` нового намерения из `next-action`. Сверка не публикует фото. После неё `next-action` назначит `change_cover` или `verify_cover`; лишь тогда begin-ui/confirm. Нельзя подтвердить восстановление по старому `on_card` без сверки. При паузе сначала выполни требуемую сверку, затем разрешённый `resume`.

Изменение условий при финальном `confirm` сохраняется в отчёте, ставит `paused_attention` и снимает подтверждение цели. После разрешённого `resume` с проверенными новыми условиями начинается новая эпоха сравнения A/B; `stop` по запросу пользователя по-прежнему может восстановить фото независимо от цены.

Скрипт атомарно сохраняет `state.json` под блокировкой. Если обновление HTML прервалось после сохранения состояния, повтори `report`; не повторяй внешнюю смену фото. При отклонённом вводе исходное состояние остаётся неизменным; копии уже прочитанных источников могут остаться в evidence и не входят в расчёт без принятого наблюдения.
