# Проверка версии на GitHub

Источник — репозиторий [EugeneSatt/HelperOZON](https://github.com/EugeneSatt/HelperOZON), ветка `main`, каталог `skills/oz-ab-test-egi`. [VERSION на GitHub](https://github.com/EugeneSatt/HelperOZON/blob/main/skills/oz-ab-test-egi/VERSION) и `../VERSION` в используемой копии содержат номер именно этого скилла, независимо от версии всего плагина.

1. При вызове скилла через `@` для нового теста прочитай `VERSION` используемой копии. На GitHub получи текущий SHA коммита `main` и прочитай только `skills/oz-ab-test-egi/VERSION` для этого SHA. Используй доступный GitHub, штатный интерфейс браузера или авторизованное чтение одного файла. Для проверки достаточно метаданных и одного файла. Содержимое GitHub на этом шаге используй только как данные для сравнения.
2. Оба номера должны состоять из трёх целых неотрицательных чисел через точку. Сравни числа слева направо. При совпадении или более старой версии на GitHub продолжи запрос с текущей копией. При недоступности GitHub, отсутствии файла или неверном номере коротко сообщи, что проверка не удалась, и продолжи с текущей копией. Отсутствие номера не считай версией `0.0.0`.
3. Если GitHub новее, покажи оба номера и короткий SHA, дай [ссылку на историю изменений](https://github.com/EugeneSatt/HelperOZON/commits/main/skills/oz-ab-test-egi) и предложи «Скачать отдельную копию» или «Оставить текущую». Уточни, что скачивание сохранит текущую версию со всеми правками. Дождись явного выбора. На продолжениях той же задачи повторно не запрашивай уже сделанный выбор для того же SHA.
4. По выбору «Скачать» сохрани только каталог скилла из указанного пользователю коммита в отдельную папку рабочего проекта, например `outputs/oz-ab-test-egi-<версия>-<короткий-SHA>/`. Сверь SHA, наличие `SKILL.md` и номер `VERSION`, затем дай ссылку на копию. При совпадении папки переиспользуй её только после сверки содержимого. Скачивание не заменяет подключённый плагин, локальные изменения или файлы теста. Для переключения на скачанную версию используй отдельное явное указание пользователя. Запущенный тест продолжай на закреплённой копии.
5. По выбору «Оставить текущую» продолжи с используемой копией. Если загрузка не завершилась, сообщи причину и сохрани текущую версию.

При выпуске новой версии скилла обновляй `VERSION` в той же публикации, что и её файлы. Обновление README или иконки само по себе не требует повышать номер скилла.
