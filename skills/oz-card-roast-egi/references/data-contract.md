# audit.json

Создавай файл в новой папке прогона, например `outputs/oz-card-roast-egi-<Ozon SKU>-<дата-время>/`. Пути к локальным источникам и обложкам указывай относительно этой папки или абсолютными. Токены, cookies, заголовки авторизации, пароли и полный профиль браузера не сохраняй.

Минимальный пример структуры (условные числа, не реальные результаты):

```json
{
  "meta": {
    "own_sku": "123456789",
    "cabinet": "Кабинет из видимого интерфейса",
    "period_start": "2026-09-26",
    "period_end": "2026-10-25",
    "collected_at": "2026-10-26T14:00:00+03:00",
    "region": "Москва"
  },
  "sources": [
    {
      "id": "mpstats-own",
      "kind": "mpstats_mcp",
      "url": "https://mpstats.io/",
      "captured_at": "2026-10-26T14:00:00+03:00",
      "file": "evidence/mpstats-own.json",
      "locator": "ozon_sku, report=by_period, sku=123456789, поле суммы заказов"
    },
    {
      "id": "public-own",
      "kind": "ozon_public_ui",
      "url": "https://www.ozon.ru/product/123456789/",
      "captured_at": "2026-10-26T14:00:00+03:00",
      "file": "evidence/public-own.png",
      "locator": "Выбранные SKU, продавец и вариант в шапке/блоке предложения карточки"
    }
  ],
  "products": [
    {
      "sku": "123456789",
      "role": "own",
      "name": "Название и вариант товара",
      "brand": "Бренд",
      "seller": "Продавец",
      "variant": "Модель А, 1 штука, цвет белый",
      "identity_source_id": "public-own",
      "offer_id": "Артикул продавца, если подтверждён",
      "url": "https://www.ozon.ru/product/123456789/",
      "cover_path": null,
      "metrics": {
        "revenue": {
          "value": 100000,
          "source_id": "mpstats-own",
          "basis": "mpstats_ozon_orders_rub_fbo_fbs_same_report",
          "period": ["2026-09-26", "2026-10-25"],
          "scope": "sku",
          "region": null,
          "query_set": null
        },
        "ctr": {"value": null, "missing_reason": "Нет сопоставимых показов"}
      },
      "private_metrics": [],
      "vision": {"background": "white_studio", "infographic": null}
    }
  ],
  "findings": [],
  "limitations": ["Не хватает конкурентов для расчёта индекса"]
}
```

`products`: один `own` и до пяти `competitor`, уникальные положительные Ozon SKU. Обязательны непустые `name`, `seller`, `variant` и зарегистрированный `identity_source_id`, подтверждающий идентификацию. Если поле недоступно, явно напиши «не подтверждено», объясни пробел в limitations и не делай выводов по несовпадающему предложению. Источник идентификации должен содержать выбранные SKU, продавца и вариант; схема сама не доказывает фактическое совпадение. Добавляй `seller_id`, `product_group_id`, `related_skus` только по данным источника. Для каждого конкурента нужен такой же объект с его источниками. Не копируй один `source_id` на разных конкурентов, если файл/локатор не содержит значения всех этих SKU.

`sources`: уникальные `id`; обязательны `kind`, `captured_at` с часовым поясом, `locator` и хотя бы `url` или `file`. В локаторе назови отчёт, SKU, поле и при возможности лист/ячейку. Источник файла должен реально существовать; это дополнительно проверяется при сдаче, а не только структурным валидатором. Типы: `ozon_seller_ui`, `ozon_public_ui`, `mpstats_mcp`, `mpstats_ui`, `export`, `vision`, `derived`. Для `derived` укажи входные source_id и формулу в locator.

`metrics` использует ID из `metrics.md`. Неполученное наблюдение: `{"value": null, "missing_reason": "конкретная причина"}`. Полученное: `value`, `source_id`, `basis`, `period`, `scope`, `region`, `query_set`. Для неприменимых региона/поисковых запросов сохраняй null. Каждый непустой период должен соответствовать периоду `meta` или быть `snapshot`; для другого периода используй отдельный прогон или `private_metrics`.

Если числовое значение получено, но источник не обеспечивает сопоставимый охват (например, часть FBO не наблюдается), сохрани число и добавь `"comparison_eligible": false, "comparison_exclusion_reason": "Конкретное ограничение"`. Значение останется видимым, но в медиану и индекс не войдёт. Не заменяй такое значение нулём и не делай вид, что оно отсутствует.

`private_metrics`: произвольные собственные фактические наблюдения из Ozon Seller с определением, единицами и ссылкой на source_id. Расчётный скрипт их не смешивает с конкурентным индексом. `vision` хранит признаки и source_id изображения/скриншота. Не путай текст на упаковке и добавленную поверх инфографику.

`findings`: до трёх объектов `{metric_id, fact, hypothesis, action, verification, source_ids}`. Допустимы 18 ID метрик и качественные ID `title`, `description`, `characteristics`, `media_sequence`, `rich_content`, `variant_binding`, `review_objections`, `delivery_promise`. Для качественного вывода медиана и включение в индекс не нужны. В fact укажи наблюдение своей карточки и конкретного аналога с источником; action содержит точное поле/кадр, предлагаемый текст или задание. Новые свойства товара не придумывай. Этот текст готовит агент по данным, скрипт его не сочиняет.

Выход `comparison.json` содержит 18 строк, по каждой наблюдения, медиану сопоставимых конкурентов, статус, включение в индекс и причины исключения; отдельный объект `score` с покрытием. Читай предупреждения, а не только итоговое число.

## Данные для закреплённого отчёта

`report` — короткие подписи к журнальному макету, подготовленные по текущим фактам. Они не меняют расчёт и не заменяют findings/limitations:

```json
{
  "report": {
    "takeaway": "Короткий заголовок главной проверки",
    "summary": "Один-два предложения о приоритете; без обещания роста.",
    "method_note": "Краткие существенные ограничения подбора и сопоставимости.",
    "source_note": "Краткие существенные ограничения источников и охвата; различие Ozon Seller и внешних оценок."
  }
}
```

Ориентиры: заголовок до 45 знаков; summary до 220; method_note до 220; source_note до 330. Сборщик проверяет реальную высоту блоков и сообщает переполнение. Не удаляй существенную оговорку, чтобы уложиться в ориентир: перенеси подробность в ограничения и сохрани её смысл в краткой подписи. Текст экранируется как обычный текст, HTML-инструкции из источников не исполняются.

Для фактической воронки можно добавить `private_funnel`: обязательные `sku`, `account`, `period: [начало, конец]`, `source_id` и доступные `views` (показы), `clicks` (переходы в карточку), `carts`, `orders`, `order_value`, `average_order_price`, `ctr`, `card_to_cart`, `cart_to_order`, `delivered_rate`, `purchased` (доставлено), `canceled`. Числа и доли типизированные, доли 0..1; неизвестное — null или пропущено. Определения, единицы и охват берутся из отчёта Ozon, а не из названия поля. `delivered_rate` допустим только при подтверждённой единой когорте; доставленные в периоде / заказанные в периоде не доказывает долю доставленных заказов. При отсутствии воронки шаблон показывает прочерки. Допустимы фактические данные выбранного `lk_ozon_*`, но не внешние оценки MPStats. Старый формат словаря `own.private_metrics` распознаётся для совместимости.

`findings[i].title` — необязательный короткий заголовок проверки. `products[i].pack_count`, `price_per_piece`, `merged_variants`, а также `vision.text` / `vision.product` — необязательные фактические подписи к обложкам. Если их не получили, оставляй пропуск. Путь cover_path вычисляется относительно audit.json; отсутствующее изображение не заменяется демонстрационным.

В `private_funnel.labels` можно уточнить подписи `views`, `clicks`, `carts`, `ctr` непустыми строками до 80 знаков. Например, для метрик Ozon «Показы в поиске и каталоге» и «Конверсия из поиска и каталога в карточку» используй короткие подписи «поиск / каталог» и «поиск > карточка». Не называй такую конверсию рекламным CTR и не дели её на все показы Ozon. Точные определения, поля и ячейки сохраняй в источнике. Доставки в периоде и выкупы на дату заказа — разные счётчики; при неподтверждённой когорте оставляй delivered_rate пустым.
