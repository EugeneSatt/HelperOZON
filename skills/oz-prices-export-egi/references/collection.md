# Получение целей и цен

1. Разбей пользовательский запрос на цели с уникальными `request_id`: `sku`, `seller_article` либо `store`. Сохрани исходное значение, не дополняя его заранее заданными магазинами. Для артикула продавца нужен магазин/кабинет; совпадение названия товара недостаточно.
2. Прочитай документацию текущего браузерного инструмента. Открой нужный товар/магазин в текущей сессии, проверь город. При работе через CUA используй только описанные методы; `evaluate` — для чтения видимого DOM. Не создавай фоновый `window.__oz`, не вызывай из read-only evaluate сетевой `fetch`, не извлекай cookies и не переходи на скрытый CDP.
3. В магазине сначала убери только собственные случайно поставленные фильтры, если это нужно для полного каталога. Читай карточки и ссылки со страницы. Проверяй принадлежность продавцу: рекомендации и рекламные плитки могут относиться к другим магазинам. Веди множество SKU и журнал страниц. Повторы в середине каталога нормальны. Пустая страница, ошибка загрузки и конец каталога — разные состояния. Максимум три попытки на временную ошибку; затем отметь неполноту и сохрани собранное.
4. Основной маршрут — обычные карточки и навигация. Если браузер допускает отображение JSON и текущий интерфейс/доступная документация подтверждает штатный маршрут Ozon, допустим запасной путь из исходного скилла: HTTPS-навигация на `https://www.ozon.ru/api/entrypoint-api.bx/page/json/v2?url=<encoded_path>`. Прочитай текст отображённого ответа и разбери в управляющем контексте. Это не разрешает вызовы скрытого состояния страницы. Если маршрут недоступен — вернись к UI, не обходи антибот.
5. В отображённом JSON `location.current.city` помогает сверить город; `nextPage` — продолжить тот же каталог. Ключи `widgetStates` с `tileGridDesktop*` могут содержать элементы со SKU. Сами ключи и структуры меняются: сначала проверь ответ. `nextPage` не должен уводить к другому продавцу/домену. Конец каталога подтверждается отсутствием следующей страницы в корректном ответе либо видимым концом выдачи; три пустых ответа без объяснения пометь как неполный сбор. Не используй лимит страниц как доказательство полного каталога.
6. На каждой товарной странице сверь выбранные SKU, продавца и вариант. Прочитай обе цены, подписи и банковское условие. Ссылку продавца и выбранный вариант сохраняй вместе с ценой. После автоматической смены предложения не приписывай цену исходному магазину. Для заданного магазина неверное предложение означает `identity_mismatch` до повторной проверки.
7. В JSON карточки `webPrice*` иногда содержит `cardPrice` и `price`. Это кандидаты, а не универсальное определение: сверяй с видимыми подписями. `originalPrice` — не база СПП. Парсер `parse_price` принимает только одну денежную сумму; строка с процентом, диапазоном или платёж/месяц требует ручного разбора.
8. Для собственных товаров скачай штатный отчёт Seller: «Цены и акции» → «Цены» → «Скачать шаблон xlsx». Скачивание не означает изменение цен: поля «Новые цены» не заполняй, файл обратно не загружай. Экспорт может игнорировать поисковый фильтр и включать весь кабинет. Для сопоставления используй точный SKU из столбца «SKU», артикул и кабинет; числовой ID строки UI может быть другим. В типовом шаблоне лист «Товары и цены», строка 2 содержит заголовки, строка 4 — определения. Кабинетная — «Предельная цена, руб.», не «Цена реализации, руб.», не зачёркнутая, не новая цена. Не фиксируй буквы столбцов в парсере: ищи заголовки.

   Для выбранных строк выполни `python3 SKILL/scripts/extract_seller_prices.py --input report.xlsx --skus SKU1 SKU2 --captured-at ISO_TIME --seller-name NAME --output cabinet-prices.json`. Время — исходная выгрузка, не время запуска скрипта. Скрипт не подтверждает продавца и условия сам: это проверяет агент. Он читает XML без стилей, поскольку штатный XLSX может иметь стили, которые не понимает openpyxl.

   Сохрани отчёт и лист/ячейки каждого SKU. Кабинетная цена может действовать во всех запрошенных городах: это явно задаётся `seller_base.regions`, а не угадывается из отсутствия города. Временной разрыв больше 15 минут — обнови витрину или оставь СПП пустой. Для чужого магазина без кабинета выгрузи зелёную/серую цену и объясни отсутствие кабинетной и СПП.
9. Сохраняй промежуточный `snapshot.json` после каждого пакета. Несколько городов записывай в `meta.regions`; ключ наблюдения включает город. Не объединяй одинаковый SKU разных городов. Перед продолжением сверь локацию и время. По завершении проверь все пары SKU × город, включая ошибки, и восстанови исходную локацию доставки.

Не покупай товар и не добавляй его в корзину для проверки цены. Не создавай расписание без запроса. Вход/CAPTCHA обрабатывай по правилам текущего инструмента. Отсутствие данных или доступа не повод молча исключить строку.
