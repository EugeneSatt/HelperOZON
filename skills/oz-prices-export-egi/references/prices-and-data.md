# Цены, расчёт и контракт данных

## Что показывать

- **Зелёная, Ozon Карта** — текущая банковская цена, если подтверждено участие Ozon Банка. Подпись «С банками» может охватывать и банки-партнёры; сохрани её отдельно в источниках.
- **Серая, без Ozon Карты** — текущая цена «С другими банками». Не зачёркнутая цена и не платёж рассрочки.
- **Кабинетная** — подтверждённое поле Seller, обычно «Предельная цена, руб.» из штатного отчёта. Смысл поля: цена, которую продавец устанавливает вручную; цена сайта не поднимается выше этого значения. Это не «Цена реализации», не выручка и не сумма выплаты.
- **СПП, %** = `(кабинетная − серая) / кабинетная`. В JSON хранится доля (0.1), Excel отображает процент (10%). Зелёная цена в формулу не входит. Другие скидки и разницы в рублях не вычисляются и не выводятся.

Это расчётное сравнение с выбранной кабинетной ценой, а не официальный показатель компенсации Ozon. Поле и его определение должны быть видны в отчёте. Нулевая подтверждённая разница — 0%. Отрицательная сохраняется с пометкой «серая выше кабинетной». Отсутствие данных — null, не 0. Деление на нулевую цену запрещено; денежные значения положительные, с точностью до копеек, валюта RUB.

Время кабинетной и серой цены по умолчанию должно отличаться не более чем на 15 минут. При большем разрыве обнови витрину. Если это невозможно, кабинетную цену с её временем можно показать, но СПП оставь пустой с причиной. Другой интервал допустим только при явном согласовании пользователя через `meta.max_spp_gap_minutes`.

## snapshot.json

`meta`: `regions` — список подтверждённых городов; для старых одиночных снимков допустим `region`. `started_at`, `finished_at` — ISO-время с часовым поясом, включающее витринные строки. Необязательные `currency` (только RUB), `seller_cabinet`, `max_spp_gap_minutes` (15), `demo` (только синтетические проверки). Отображение времени Excel: `display_utc_offset_minutes` (180) и `display_timezone_label` («МСК»). Исходные ISO-метки не меняй.

`requests`: непустой список `{id, type, value}`. Типы `sku`, `seller_article`, `store`. Необязательные `seller_id`, `seller_url` ограничивают продавца. SKU — положительное числовое значение, записанное как текст. Для всех целей проверяется каждый город из `meta.regions`.

`sources`: список `{id, kind, captured_at, locator, url?, file?}`. Хотя бы URL или реальный файл обязателен. `kind`: `ozon_public_ui`, `browser_json`, `ozon_seller_ui`, `export`, `user_provided`. `locator` указывает точный SKU, предложение, поле или лист/ячейки. Подлинность источника проверяет агент, не валидатор. В исходниках можно хранить путь к файлу; в пользовательской книге показывай URL или название отчёта без служебных путей.

`catalogs`: для каждой store-цели `{request_id, seller_id, source_id, discovered_skus, complete, stop_reason, expected_count?}`. `complete=true` допустимо только при подтверждённом конце каталога `end_of_catalog`, совпадении ожидаемого числа SKU (если известно) и обработке всех SKU во всех городах. Повтор плитки не означает конец.

`rows`: список наблюдений. Основные поля успешной строки:

```json
{
  "request_ids": ["r1"], "sku": "1000000001", "offer_id": "TEST-1",
  "title": "Условный товар", "seller_id": "1001", "seller_name": "Тестовый продавец",
  "seller_url": "https://example.com/seller", "variant": "500 мл; 1 шт.",
  "identity_verified": true, "identity_source_id": "public-1",
  "region": "Москва", "captured_at": "2026-11-05T17:20:00+03:00",
  "status": "ok", "url": "https://example.com/product",
  "other_banks": {"value": 1000, "source_id": "public-1", "label": "С другими банками"},
  "bank_offer": {"value": 900, "source_id": "public-1", "label": "С банками", "includes_ozon_bank": true},
  "seller_base": {
    "value": 1250, "source_id": "seller-1", "label": "Предельная цена, руб.",
    "definition": "seller_price_cap", "sku": "1000000001", "seller_id": "1001",
    "seller_url": "https://example.com/seller", "variant": "500 мл; 1 шт.",
    "regions": ["Москва", "Краснодар", "Нижний Новгород"], "conditions_comparable": true
  },
  "notes": "Условия и ограничения"
}
```

Пример синтетический, не рыночные данные. Старое определение базы `seller_after_own_promos_before_platform_discount` также поддерживается. В базе вместо списка `regions` допустим одиночный `region`. Совпадение продавца подтверждается по ID или точной ссылке. Не подставляй SKU другого варианта/продавца. При неверной привязке кабинетная цена в строку не переносится.

`seller_base` необязателен. `other_banks`, `bank_offer`, `seller_base` для неизвестного — null или объект с `value:null` и `missing_reason`. Участие Ozon Банка при неизвестности — `includes_ozon_bank:null`; зелёная колонка пустая. Не придумывай привязку ради прохождения проверки.

Статусы: `ok`, `partial`, `unavailable`, `not_found`, `load_error`, `identity_mismatch`. Для ошибки допустим `sku:null`; обязательны цель, город, время, статус и `notes` с причиной. Ошибки и отсутствие товара сохраняются в таблице.

## Обработка и выход

`prepare_export.py` проверяет контракт и привязки, считает только процент СПП через Decimal. Ключ наблюдения — SKU + продавец + вариант + город. Для нескольких снимков одного ключа выбирается последний, старые остаются в `snapshot.json`. Разные цены одного ключа в одну секунду — конфликт. Каждый отсутствующий SKU × город получает явную строку ошибки, а не исчезает. Наличие строки отдельно от наличия обеих цен; статус без наличия не означает успешную пару цен.

`extract_seller_prices.py` читает штатный XLSX через ZIP/XML, ищет заголовки, выбирает точные SKU и сохраняет кабинетную цену, артикул, название, исходный лист/строку и определение поля. Дубли SKU требуют ручного разрешения. Скрипт не доказывает соответствие кабинета/продавца и не меняет исходный файл.

Excel содержит «Цены» и «Сбор». Зелёная/серая колонки окрашены по смыслу. Показываются кабинетная цена и времена обоих источников; только одна скидочная метрика — СПП %. Книга — снимок; ручные правки не запускают повторный сбор/нормализатор. Идентификаторы — текст, цены и даты — числовые. CSV: UTF-8 BOM, `;`, десятичная запятая, доли (0,1 = 10%), русские статусы, защита текстовых формул.
