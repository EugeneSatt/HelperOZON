`url`, `page_title`, `product_type_terms`, `facts`, якоря и конфликты заполняй после чтения карточки. `description_limit` — пример, не универсальный лимит. Для `child_diapers` и `laundry` скрипт знает базовые типы; для `generic` он пытается извлечь распространённый тип из названия, а если это невозможно — требует явный список.

`required_product_anchors` и `protected_broad_terms` обязательны как просмотренные списки. Оба могут быть пустыми только после соответствующей ручной проверки. Для якоря укажи допустимые варианты написания; аудит ищет их как отдельные фразы.

Конфликт считается разрешённым, когда у записи есть `status: "resolved"` и подтверждённое `resolution`. До этого подготовленный файл содержит блокирующий конфликт.

`prepare`:

- ищет одно- или двухуровневую шапку в первых 20 строках;
- при сбое обычного чтения `.xlsx` извлекает значения напрямую из OOXML;
- сохраняет все исходные столбцы в `source_metrics`, а сведения о шапке — в `source_metadata`;
- определяет профиль, категории, релевантность, покрытие якорей и подозрительные бренды;
- сортирует `accepted_rows` по релевантности, покрытию якорей, специфичности и только затем популярности.

```bash
python3 scripts/seo_pipeline.py prepare --config /abs/config.json --output /abs/prepared.json
```

## Descriptions JSON

```json
{
  "limit": 2000,
  "overlap_policy": "strict",
  "broad_term_policy": "strict",
  "protected_broad_terms": ["подгузники"],
  "key_tiers": {
    "core": ["ночные трусики подгузники", "подгузники трусики 5"],
    "extension": ["подгузники трусики 17 шт"],
    "experimental": ["подгузники трусики xl"]
  },
  "variants": [
    {
      "name": "Основной",
      "strategy": "core_strict",
      "text": "...",
      "keys": ["ночные трусики подгузники", "подгузники трусики 5"],
      "seo_sentence_count": 2
    },
    {
      "name": "Расширенный",
      "strategy": "relevant_expansion",
      "text": "...",
      "keys": ["ночные трусики подгузники", "подгузники трусики 5", "подгузники трусики 17 шт"],
      "seo_sentence_count": 3
    },
    {
      "name": "Тестовый",
      "strategy": "controlled_test",
      "text": "...",
      "keys": ["ночные трусики подгузники", "подгузники трусики 5", "подгузники трусики xl"],
      "seo_sentence_count": 3
    }
  ]
}
```

`key_tiers` обязателен. Все его значения должны быть принятыми ключами, а один ключ не может находиться в нескольких уровнях. `Основной` равен `core`, `Расширенный` равен `core + extension`, `Тестовый` равен `core + experimental`. Внутри каждого варианта вложенные пары ключей запрещены. Все ключи перечисляются по популярности от большей к меньшей; следующий ключ не может быть популярнее предыдущего. Фиксированного максимума числа ключей нет: используй столько релевантных невложенных запросов, сколько вмещает лимит без ухудшения текста.

Только первые `seo_sentence_count` предложений привязаны к ключам и начинаются с них. После них должны идти минимум два обычных предложения. `seo_sentence_count` должен совпадать с числом `keys`.

`overlap_policy`:

- `strict` — рабочий режим: по одному буквальному вхождению каждого ключа;
- `warn` — лишние совпадения становятся предупреждениями;
- `prefer_specific` — совместимость со старыми файлами; вложенные пары всё равно блокируются аудитом.

```bash
python3 scripts/seo_pipeline.py audit --prepared /abs/prepared.json --descriptions /abs/descriptions.json --output /abs/audit.json
```

Код `0` означает, что `technical_status`, `commercial_status` и `global_status` равны `pass`. Код `2` означает, что аудит создан, но минимум один статус не пройден.

## Excel

Собери один файл с листами:

1. `SEO-тексты`: стратегия, копируемый текст, проверочная версия с синими ключами, символы, лимит, остаток, число SEO-предложений, технический статус, коммерческий статус, общий статус.
2. `Использованные ключи`: вариант, стратегия, роль ключа (`core`, `extension`, `experimental`), ступень лесенки, ключ, популярность, изменение популярности к предыдущей ступени, уровень релевантности, `selection_rank`, покрытые якоря, источник, категория, фактические и ожидаемые вхождения, статус; рядом — бюджет защищённых слов и краткая гипотеза для каждого экспериментального ключа.
3. `Ключевая база`: исходный и нормализованный запрос, все исходные показатели, файл и строка, seed-запрос, порог, профиль и категории, релевантность, специфичность, покрытые якоря, найденные бренды, решение и причина, варианты использования. Для каждого принятого, но неиспользованного запроса добавь причину неиспользования: вложенность с выбранным ключом, лимит, повтор смысла или ухудшение читаемости.
4. `Данные товара`: URL, название, целевой бренд и алисы, профиль, все факты с источниками, обязательные якоря и их покрытие, противоречия и решения.

Если частичное форматирование ячейки недоступно, сохрани обычный текст и ниже покажи проверочные предложения в двух колонках: синий ключ и продолжение.

Цвета: ключ — синий; пройдено — зелёный; ошибка — красный; предупреждение — жёлтый; исключение — серый. Цвет не заменяет текстовый статус.

Перед выдачей пересчитай книгу, проверь формулы, отрисуй все листы, проверь переносы, ширины, фильтры, закрепление заголовков, соответствие свежему `audit.json` и прослеживаемость утверждений до `Данные товара`.
